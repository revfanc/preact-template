# Landing 开发约束

适用于 `apps/landing`。开发命令和预渲染示例见 [README](./README.md)，完整分层规则见 [ARCHITECTURE](./ARCHITECTURE.md)。按任务阅读对应详细说明，不另建重复规则或无实际用途的架构层。

## 目录与分层

- 活动入口使用 `src/pages/p1/<code>/index.tsx` 等目录形式，只装配参数、状态、UI 和导航。组件使用 `src/components/<name>/index.tsx`，样式就近放 `index.module.css`；辅助组件不放在 `pages` 中。
- 默认沿用 UI → 场景 hook → store action → API。store 管业务数据、请求结果和 pending/error；hook 组织反馈、导航和用户流程；通用 UI 通过 props/action 通信。简单操作可直接调用 action，不强制增加转发 hook。
- 场景 hook 使用 `src/hooks/use-<name>/index.ts(x)`；store 的接入 hook 放在 `src/stores/<业务>/hooks.ts`，数据工厂和 action 放在该模块 `index.ts`。跨模块用 `@/`，模块内部用 `./`。

## 状态与生命周期

- 先确定实例所有者、共享范围和销毁时机，再写 store。业务状态放入最小共同作用域，局部动画和布局测量可留在 UI；不创建模块级业务单例，不因未来可能共享就放进应用集合。
- `useLocalXxxStore()` 创建局部实例，`useAppStores()` 获取已有集合，`useStore(store)` 订阅传入实例。需要共享时传递同一实例，不在各消费者重复创建；Provider 只传递实例，创建者负责清理。
- store 不直接展示 Toast、Loading、Modal 或执行导航。异步任务、轮询和监听由所属实例清理；销毁后不得回写数据或继续触发业务行为。具体文件职责、Modal Context 桥接和持久化见 [Stores 说明](./src/stores/README.md)。

## 预渲染与首屏

- 静态活动页按需直接导出 `const prerender = true`，无需逐页修改 Vite 配置；动态参数路由不支持该标记。保留根 `index.html` 作为 SPA 回退入口，普通活动开发不新增业务首页或改造路由、入口和构建机制。
- 模块顶层、组件 render、store 工厂和初始状态计算保持无浏览器副作用。请求、缓存恢复、SDK、反馈、History 注册和埋点从客户端 effect 或事件启动，首帧不依赖时间、随机数或浏览器缓存。
- 预渲染只输出可公开共享的内容；同一路径不同 query 共用 HTML，不把渠道价格、用户信息或订单状态写入静态产物。hydration 首帧与 HTML 保持一致，JS 未接管或业务未就绪时禁止提交。详细规则见 [业务开发约定](./README.md#业务开发约定)。

## 渠道与异步隔离

- 渠道、用户或订单身份变化时，明确重置或重建对应实例，取消旧任务并防止旧响应覆盖新状态。SPA 可能复用组件，初始化不能只依赖首次挂载；普通 query 变化也不等于业务身份变化。
- 当前渠道上下文使用 `useChannelStore()` 读取，依赖渠道的链接和代码跳转使用 `useNavigation()`；其白名单、首屏启用时机及缺失参数处理见 [渠道上下文与导航](./README.md#渠道上下文与导航)。当前没有真实配置请求，不把 `initialized` 当作接口就绪。
- 持久化显式选择字段、版本、校验和业务 key，在客户端恢复；不整份缓存 store，不用旧渠道缓存覆盖当前 URL 上下文。恢复完成前禁止相关编辑和提交，订单结果以接口确认。
- 提交防重放在 action 内，按钮状态由同一 pending 驱动；重试遵循接口语义，不给提交类操作统一自动重试。接口未知时明确缺少的契约，不猜测请求参数或业务成功条件。

## 公共能力与样式

- 复用 `@packages/request`、公共 API、反馈、组件、Browser 和主题能力，通过包的公开入口引入并声明依赖；不导入 Agreement 源码或正式代码之外的测试夹具。普通业务不顺带修改共享包和构建配置，确需调整时验证受影响的消费者。
- 沿用 CSS Modules、375px 设计宽度下 px 转 rem 和单个单词的主题变量。保留外链 CSS 支持 SPA 导航及动态状态，不因部分样式已内联就删除资源；新增浏览器 API 和第三方库需检查仓库兼容目标。
- 图片导入、`public` 地址、CDN 和首屏加载遵循 [图片引用](./README.md#图片引用)；默认静态导入，不为规避小分包统一改成手写路径或全局图片总表。

## 验收与提交

- 业务改动运行格式、Lint、类型检查和相关测试，验证 test/prod 构建；公共包或构建变更按[质量说明](../../docs/quality.md)覆盖两个应用。命令入口见 README，测试夹具与正式页面分离。
- 页面同时验证直接访问、刷新和 SPA 跳转；预渲染页面检查实际 HTML、弱网首屏和 hydration 后交互。涉及数据时验证渠道切换、缓存恢复、失败重试、防重和资源清理，不能仅凭开发模式页面正常判断通过。
- 纯文档修改只检查格式、链接和内容准确性。相关检查通过后 commit，说明修改和实际验证范围；检查失败时修复原因，不通过跳过测试或放宽规则来提交。现代浏览器测试不代表最低版本设备验收。

依赖边界已有自动检查；业务状态归属、接口语义及生命周期仍需按上述约定审查，不能以检查通过代替业务验证。
